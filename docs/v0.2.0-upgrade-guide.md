# Upgrade Guide: v0.1.x to v0.2.0

- [Org managed credential output rename (Breaking Change)](#org-managed-credential-output-rename-breaking-change)

## Org managed credential output rename (Breaking Change)

`modules/create` replaces the flat credential outputs with one sensitive object, `org_managed_credential`, so bootstrap secrets from `mongodbatlas_organization` are not confused with future rotatable module-owned credentials.

### Who is affected?

Callers of `modules/create` that read `public_key`, `private_key`, `client_id`, or `client_secret`.

Unaffected: `modules/existing` callers, and import-only flows that never used create credential outputs.

### Required action

Update HCL references to the nested fields:

```terraform
# Before
module "atlas_org" {
  source = "mongodb/organization/mongodbatlas//modules/create"
  # ...
}

provider "mongodbatlas" {
  client_id     = module.atlas_org.client_id
  client_secret = module.atlas_org.client_secret
}

# After
module "atlas_org" {
  source = "mongodb/organization/mongodbatlas//modules/create"
  # ...
}

provider "mongodbatlas" {
  client_id     = module.atlas_org.org_managed_credential.client_id
  client_secret = module.atlas_org.org_managed_credential.client_secret
}
```

Same path change applies for `public_key` and `private_key` under `org_managed_credential`.

### State migration

No state migration required. Outputs are not resources; update references and re-plan.

### Why the change?

Org-resource secrets created at organization create time are bootstrap-only. Naming them as flat `client_id` / `public_key` read like steady-state credentials and would clash with a future rotatable `current_credentials` output from a dedicated rotation workflow.
